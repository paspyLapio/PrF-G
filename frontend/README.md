# PrF-G front end (React + TypeScript)

Full-screen demo: a simulated lunar flight on a live trajectory, the cabin telemetry the vehicle already has,
and the PrF-G dashboard (status, reasons, crew options, materials, Ask PrF-G, neural-network slot, decision log).

```bash
cd frontend
npm install
npm run dev                                   # http://localhost:5173, on-board engine only
VITE_API_URL=http://localhost:8000 npm run dev  # live backend (run api/ first)
npm run build                                 # -> dist/ (static, any host)
```

## Deploy to Cloudflare Workers (workers.dev)

The whole site runs as one Cloudflare Worker:

| Path | What it serves |
| --- | --- |
| `/` | Main menu with three buttons: Presentation, Repository, Live demo (`site/index.html`). |
| `/presentation/` | The deck, read live from the repo's `presentation/` folder (see `presentation/README.md`). Uploading a new file to the repo updates the site without a redeploy. |
| `/repo` | Redirect to the GitHub repository (`GITHUB_REPO`). |
| `/demo/` | The simulation (this Vite app). |
| `/api/*` | Forwarded to the FastAPI backend, so the browser only talks to one origin (no CORS). |

```bash
cd frontend
npm install
npx wrangler login        # once, opens the browser
npm run deploy            # builds with VITE_API_URL=/api, then wrangler deploy
# -> https://prf-g.<your-subdomain>.workers.dev
npm run dev:worker        # same thing locally at http://localhost:8787
```

- **Backend URL**: `BACKEND_URL` in `wrangler.jsonc` (default `https://prf-g-api.onrender.com`). Set it to `""` to
  run on the on-board engine only. Change it without redeploying code under Worker → Settings → Variables.
- **Sleeping backend**: if the backend takes longer than `BACKEND_TIMEOUT_MS` (8 s) the Worker answers 503 and the app
  switches to its on-board engine, as it does with no backend. Open the backend's `/docs` a minute before presenting.
- **Deploy from GitHub instead**: Cloudflare dashboard → Workers & Pages → Create → Import a repository → this repo,
  root directory `frontend`, build command `npm run build:worker`, deploy command `npx wrangler deploy`.
- **Presentation**: put `presentation.pdf` (or `presentation.pptx`, or `link.txt` with a Google Slides/Canva link)
  in the repo's `presentation/` folder. The repo must stay public; change `GITHUB_REPO`, `GITHUB_BRANCH`,
  `PRESENTATION_DIR` in `wrangler.jsonc` if it moves.
- Files: `wrangler.jsonc` (config), `worker/index.ts` (routes, presentation, `/api` proxy), `site/` (menu and
  presentation pages), `.env.worker` (build mode `worker`: demo goes to `dist/demo`, `site/` is copied around it).
  `npm run build` without `--mode worker` is unchanged, so the Render static site keeps working.

## How it is built

| File | Role |
| --- | --- |
| `src/lib/engine.ts` | Evidence engine: the same status rules as `api/app/engine.py`, run on board. |
| `src/lib/api.ts` | Client for the backend `/index` and `/ask`. |
| `src/lib/sim.ts` | Mission simulation: telemetry, events, crew notices (new → acknowledged → resolved, see docs/DECISIONS.md §6), crew options, decision log. Uses the backend when it answers, falls back to the on-board engine after two failed calls. |
| `src/lib/mission.ts` | Phases, presets, design atmospheres, illustrative vehicle numbers. |
| `src/lib/trend.ts` | O₂ trend projection to the caution point and the tested-evidence edge (docs/DECISIONS.md §7). |
| `src/lib/nn.ts` | Neural-network slot (firewalled, display only). |
| `src/components/` | `Sky` (canvas trajectory), `Hud` (clock, status ring, telemetry, timeline, toast), `Dashboard`, `Launch` (mission setup and pre-flight check). |
| `src/data/evidence.json` | Generated by `python3 tools/export_frontend_data.py` from `data/`. Do not edit by hand. |

## Neural network (P3)

With `VITE_API_URL` set, the dashboard's Neural network tab polls `GET /mlp` every 2 s while it is open and shows
P3's model beside the evidence engine for each exposed material, with its training-domain flags.
`.env.development` points `npm run dev` at `http://localhost:8000`.

### Plugging in a local model instead

The model is never imported by the simulation, so it cannot change status, alerts or options. Register it at runtime:

```js
window.PrFG.connectMLP("MLP v1", (x) => ({ label: "Predicted spread", value: predict(x), unit: "mm/s" }));
// x = { o2_pct, pressure_kpa, flow_cm_s, gravity_g, thickness_mm }
```

Ship weights as JSON (no .joblib/.pkl) and write `predict` as plain TypeScript in `src/lib/nn.ts`.

Keys: Space pauses, D opens the dashboard, Esc closes it.
